# Mermaid npm and README discoverability

## Evidence

- Mermaid's npm description names Markdown-like diagram syntax and several diagram kinds, while its keyword list uses broad search terms such as `diagram`, `markdown`, `flowchart`, `sequence diagram`, `gantt`, `mindmap`, and `er diagram`. [npm package page](https://www.npmjs.com/package/mermaid) [npm metadata](https://registry.npmjs.org/mermaid/latest)
- Mermaid's README opens with a one-line promise, then gives a prominent Live Editor link and a compact route to documentation, getting started, CDN, and community. It follows with a linked contents list, an explanation of the problem it addresses, and diagram examples that link to syntax documentation and editable live examples. [Mermaid README](https://github.com/mermaid-js/mermaid/blob/develop/README.md)
- Mermaid's official guide offers five paths to use the product, including the Live Editor, integrations, the JavaScript API, and npm dependency installation. The deployment guidance shows `npm i mermaid`; the API example imports Mermaid from a CDN and calls `mermaid.initialize({ startOnLoad: true })`. [Mermaid User Guide](https://mermaid.js.org/intro/getting-started.html) [Mermaid introduction](https://mermaid.js.org/intro/)
- The local package description calls AzeForge a deterministic AzeMark compiler that emits self-contained HTML, SVG, PNG, and PDF. Its keywords are `azemark`, `markdown`, `publishing`, `pdf`, and `svg`. [local package manifest](https://github.com/aruzone/aze-forge/blob/main/package.json)
- The local README already has a clear AzeMark promise, installation, and several copyable, end-to-end examples for a first document, equations, tables, diagrams, formats, diagnostics, grammar, and live preview. The README links the authoring guide and language index, but its opening area does not provide a direct playground or a single getting-started route beside the product promise. [local README](https://github.com/aruzone/aze-forge/blob/main/README.md)

## Deltas and recommendation

AzeForge has more execution detail than Mermaid's entry material, but the first screen makes a reader work before they can try the compiler or find the documentation map. Keep the existing installation and first-document example, then add an opening action row with `npm install -g @aruzone/aze-forge`, a link to the authoring guide, and a link to `azeforge serve` as the local preview path. [local README](https://github.com/aruzone/aze-forge/blob/main/README.md) [Mermaid README](https://github.com/mermaid-js/mermaid/blob/develop/README.md) [Mermaid User Guide](https://mermaid.js.org/intro/getting-started.html)

Broaden npm keywords only where the package can substantiate them: `technical-publishing`, `technical-documentation`, `diagram`, `equation`, `latex`, `html`, and `pdf` match the compiler's documented inputs and outputs. Do not borrow Mermaid's diagram-type keywords, because AzeForge documents Mermaid as a bounded escape hatch rather than its primary language. [local package manifest](https://github.com/aruzone/aze-forge/blob/main/package.json) [local README](https://github.com/aruzone/aze-forge/blob/main/README.md) [Mermaid npm package page](https://www.npmjs.com/package/mermaid)

Promote AzeMark as the readable, typed authoring language and AzeForge as the deterministic compiler. That pairing preserves the distinction already present in the package and README, while making search and first-use intent easier to understand. [local package manifest](https://github.com/aruzone/aze-forge/blob/main/package.json) [local README](https://github.com/aruzone/aze-forge/blob/main/README.md)
