# Exclude the derived numbering projection from content identity

The numbers a reader sees — figure, table, equation, theorem-family and example numbers, citation numbers with author–year disambiguation suffixes, footnote marker numbers, auto labels and accessible names — are computed deterministically from authored content in a two-pass traversal and live in the Document as the derived numbering projection, but `contentHash` covers only the authored inputs: identifiers, caption/title text, `number:` flags, reference and citation spans with their forms and locators, footnote labels and content, bibliography record fields, and the `citation-style` metadata key. Including the derived values would double-count the authored order the hash already carries and would make a renumber-only edit look like an identity change, while excluding them preserves ADR 0002's guarantee that formatting-equivalent edits retain document identity: every derived value stays exactly reproducible from hashed content, and stale projections cannot survive a compile because the projection recomputes each pass. The boundary mirrors renderer-derived geometry and composed labels, which remain fingerprint-only — with one asymmetry: the numbering projection is format-independent Document data shared by every Renderer, not a per-target rendering fact, so it is excluded from identity without being demoted to a fingerprint.
