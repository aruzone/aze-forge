# Separate P0 and pilot release gates

AzeForge uses two cumulative release gates: P0 proves the CLI and four-format compiler with one Golden report, while P0.5 begins from a released P0 and adds semantic Circuit fixtures, adapter/platform evidence, a frozen pilot-driven Circuit syntax, and lecturer approval. One versioned Acceptance catalog maps every observable contract to unit, golden, integration, compatibility, or human evidence; structural and semantic checks are authoritative, with tightly bounded visual comparisons only where an Artifact format preserves no inspectable semantics. This prevents optional Circuit infrastructure from delaying P0, prevents attractive snapshots from concealing wrong meaning, and makes missing, flaky, waived, or stale evidence release-blocking rather than advisory.
